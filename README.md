# CS SOFT SERVER

Два варианта в одном репозитории:

| Что нужно | Куда смотреть |
|---|---|
| **Настоящий CS2-сервер** с `connect IP:27015` | **[deploy/cs2/README.md](deploy/cs2/README.md)** — Docker + GSLT + плагин софтов |
| Браузерная версия (работает сразу, без VPS) | этот файл, ниже |

---

# Часть 1. Настоящий CS2 (Source 2)

Нужен VPS (Ubuntu 24.04, 4 ГБ RAM, 80 ГБ), Docker, GSLT-токен Steam.

```bash
ssh root@ТВОЙ_IP
git clone https://github.com/versus3927/cs-soft-server.git && cd cs-soft-server
bash deploy/cs2/install.sh      # ставит Docker, порты, генерирует токен моста
nano deploy/cs2/.env            # SRCDS_TOKEN="токен с steamcommunity.com/dev/managegameservers"
cd deploy/cs2 && docker compose up -d
```

Через 10–40 минут (качается ~60 ГБ) сервер готов, и у тебя есть ссылка:

```
connect ТВОЙ_IP:27015
```

Плагин, который каждый раунд раздаёт игрокам случайный софт, — в `deploy/cs2/cs2-soft-plugin`
(CounterStrikeSharp). Подробности, честный список того, что реально работает на Source 2,
и разбор проблем — в **[deploy/cs2/README.md](deploy/cs2/README.md)**.

**Бесплатно?** Полностью бесплатно — только через [playit.gg](deploy/cs2/README.md#бесплатные-варианты-и-где-подвох)
(туннель UDP на твой ПК, free-тариф с оговорками). Oracle Always Free даёт бесплатный VPS,
но он ARM — CS2 под x86 там не пойдёт. Самый надёжный путь — дешёвый x86-VPS за €4–7/мес.

**Railway для CS2 не подходит:** нет UDP-порта и 60 ГБ диска под образ.

# Часть 2. Браузерная версия

Браузерный CS-подобный deathmatch-сервер, в котором **каждому игроку каждый раунд выдаётся случайный софт**: аимбот, вх, быстрая стрельба, без отдачи, банихоп, спидхак, триггербот, радар, бесконечные патроны, двойной урон и мемный спинбот. Софты реально работают на сервере — это не картинка, а игровая механика.

Побеждает тот, кому повезло с дропом и кто успел этим воспользоваться.

## Как зайти

### Вариант 1 — локально (проще всего, 2 минуты)

```bash
git clone <этот-репозиторий>
cd cs-soft-server
npm install
npm start
```

Открыть в браузере: **http://localhost:3000**
Вписать ник → «В ИГРУ». Всё, ты на сервере. Чтобы играть с другом — он открывает тот же адрес; если играет с другого компьютера в той же сети, отдай ему `http://<твой-IP>:3000` (порт 3000 пробросить в файрволе).

### Вариант 2 — публичный сервер (чтобы зайти по ссылке с любого устройства)

Любой хостинг, который умеет Node.js:

```bash
# на сервере/в контейнере
PORT=3000 npm start
```

Сервер слушает `0.0.0.0`, поэтому подойдёт Render / Railway / Fly.io / VPS + nginx-прокси. Открываешь выданный домен или IP:порт — и играешь.

> Проверка, что сервер поднялся: `curl http://localhost:3000/health` → `{"ok":true,...}`


## Деплой на Railway (пошагово)

1. Зайди на [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo** → выбери `versus3927/cs-soft-server`.
2. Если проект спросит ветку — бери **main** (после мержа PR с кодом) или ветку `arena/d9485506-cs-soft-server`.
3. Railway сам соберёт Node-проект (`npm install`, `npm start`) — `railway.toml` уже в репозитории, healthcheck стоит на `/health`.
4. Вкладка **Variables** — **ничего добавлять не нужно**: `PORT` Railway подставляет сам, остальное работает на дефолтах. Если хочешь свои настройки, добавь, например:
   - `ROUND_TIME=45`
   - `DOUBLE_SOFT_CHANCE=0.5`
   - `MAX_PLAYERS=20`
5. Вкладка **Settings → Networking** → **Generate Domain** → получишь ссылку вида `https://cs-soft-server-production.up.railway.app`. Открывай её и играй — заходить можно с телефона и с любого компьютера.
6. Обновить игру после правок: просто `git push` в ту ветку, которую деплоит Railway — пересборка автоматическая.

Проверка, что сервер живой: открой `https://твой-домен.up.railway.app/health` — должен вернуться `{"ok":true,...}`.

**Важно про Railway:** не задавай `PORT` вручную и не меняй `HOST` — платформа сама передаёт порт и проксирует на него трафик. Сервер уже слушает `0.0.0.0`.

**Альтернатива без GitHub-мержа** (деплой прямо из этой ветки локально):

```bash
npm i -g @railway/cli
railway login
railway init
railway up
railway domain
```


## Где взять ссылку на сервер

**Адрес сервера — это его веб-ссылка, а не `connect IP:порт`.**

| Где запущено | Ссылка выглядит так |
|---|---|
| Railway | `https://имя-проекта.up.railway.app` (Settings → Networking → Generate Domain) |
| VPS / комп в локальной сети | `http://IP:3000`, например `http://192.168.0.10:3000` |
| Свой компьютер | `http://localhost:3000` |

Готовая ссылка видна **прямо в меню игры**: блок «СЕРВЕР» — там адрес, кнопка «КОПИРОВАТЬ» и текущий онлайн `N / 16`. Скидываешь её другу — он открывает в браузере и попадает в тот же матч.

Почему не как на CyberShoke: там сервер поднимается для клиента CS:GO/CS2, и в консоли Steam ты пишешь `connect 1.2.3.4:27015`. Здесь игра живёт в браузере, поэтому заход — по обычному URL. Ничего скачивать не нужно, и софты раздаются сервером, а не читом в клиенте.

API, если нужен адрес программно: `GET /api/server` →
```json
{"name":"CS SOFT SERVER","address":"localhost:3000","connectAddress":"192.168.0.10:3000",
 "players":3,"maxPlayers":16,"round":2,"state":"live","softs":11,"doubleChance":0.15}
```


## База данных (Railway Postgres и не только)

История раундов и статистика игроков пишутся в PostgreSQL, если задан `DATABASE_URL`.

**На Railway:**
1. В проекте: **New → Database → PostgreSQL**.
2. Открой сервис приложения → **Variables** → **New Variable** → **Add Reference** → `DATABASE_URL` из сервиса Postgres.
   (Railway сам подставит строку подключения по приватной сети — наружу порт открывать не нужно.)
3. Redeploy. В логах увидишь `[db] PostgreSQL подключён, схема применена`.

Схема создаётся сама при старте (`CREATE TABLE IF NOT EXISTS`): `rounds`, `round_softs`, `player_soft_stats`.

**Локально / на VPS:**
```bash
docker run -d --name cssoft-pg -e POSTGRES_PASSWORD=pass -p 5432:5432 postgres:16
DATABASE_URL=postgresql://postgres:pass@localhost:5432/postgres npm start
npm run db:check      # проверка подключения и содержимого
```

**Без базы всё тоже работает:** `DATABASE_URL` пустой → история живёт в памяти (последние 200 раундов),
ничего не падает. Если база отваливается во время игры, раунд просто не сохраняется — игра идёт дальше.

Что появляется с базой:

| Эндпоинт | Что отдаёт |
|---|---|
| `GET /api/stats/me?name=Ник` | место в лидерборде, число раундов, любимые софты |
| `GET /api/stats/rounds?limit=20` | история раундов с дропами |
| `GET /api/stats/player?name=Ник` | сколько раз какой софт выпадал |
| `GET /api/stats/leaderboard` | топ игроков по числу раундов |

В игре сверху появляется строка: `место: #2 · раундов: 7 · чаще всего: aimbot · БД`
(если базы нет — вместо `БД` будет `ПАМЯТЬ`).

**Чего база не решает для настоящего CS2:** Railway не пробрасывает UDP и не даёт 60 ГБ под образ игры
(volume на Hobby — до 5 ГБ, на Pro — до 1 ТБ). Поэтому сам игровой сервер CS2 всё равно ставится на VPS
(см. [deploy/cs2/README.md](deploy/cs2/README.md)), а Railway может держать базу и веб-часть.

## Управление

| Действие | Клавиша |
|---|---|
| Движение | `W` `A` `S` `D` (или стрелки) |
| Прицел | мышь |
| Стрельба | ЛКМ (зажми — автомат) |
| Перезарядка | `R` |
| Пауза/меню | `Esc` |

На телефоне: стик слева — движение, свайп по экрану — прицел, кнопки «ОГОНЬ» и «R» справа.

## Правила сервера

- Раунд длится **60 секунд**, потом **8 секунд** перерыва с таблицей итогов и следующим дропом.
- В начале каждого раунда **все живы, HP 100, магазин полный**, все софты перебрасываются заново — прошлый раунд ничего не значит.
- Убил → +1 в счёт раунда. Умер → респавн через 2.5 секунды в дальней точке карты.
- Шанс **двойного дропа — 15%**: тогда у тебя два софта одновременно.
- Аимбот и триггербот не стреляют через стены: работает только видимая цель.

## Структура проекта

```
server/index.js     HTTP + socket.io, раздача статики, /api/softs, /health
server/game.js      игровой цикл 30 Гц: движение, стрельба, раунды, урон, респавн
server/softs.js     пул софтов, редкости, веса и ролл дропа
server/map.js       карта арены (симметричная, 40x24 тайла) и точки респавна
public/index.html   меню и HUD
public/client.js    рендер на canvas, ввод, HUD, радар, эффекты
public/style.css    оформление
scripts/            автотесты (npm test)
```

Сервер авторитетный: клиент отправляет только ввод (направление, кнопки), все попадания, урон и дроп считаются на сервере — читерить через консоль браузера не выйдет.

## Настройки

Переменные окружения:

```bash
PORT=3000            # порт
ROUND_TIME=60        # длительность раунда, сек
INTERMISSION=8       # длительность перерыва, сек
```

## Тесты

```bash
npm test
```

- `combat-test.js` — проверяет, что каждый софт реально меняет механику, что аимбот убивает, пули останавливаются стенами и софты меняются каждый раунд.
- `smoke-test.js` — поднимает сервер, подключает двух ботов, проверяет HTTP, выдачу софтов, раунды и снапшоты.
- `client-test.js` — прогоняет клиент в jsdom и ловит ошибки рендера/HUD.
